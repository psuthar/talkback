# `llm_call_log` row shape (contract)

This file is the **contract** for [Slice 5 (SCRUM-568)](https://suthar-team.atlassian.net/browse/SCRUM-568)
to implement the Postgres table, and for Slices 3, 4a, 4b, 4c to
populate when they call into the shared logger
(`internal/guardrails/log.go` — `LogLLMCall(ctx, row)`).

## Table

```sql
CREATE TABLE llm_call_log (
  id                   uuid        PRIMARY KEY,
  ts                   timestamptz NOT NULL DEFAULT now(),
  site                 text        NOT NULL,                 -- enum, see below
  model                text        NOT NULL,
  user_id              uuid        NULL,
  session_id           uuid        NULL,
  prompt_hash          text        NOT NULL,                 -- sha256(prompt), hex
  input_tokens         int         NULL,
  output_tokens        int         NULL,
  latency_ms           int         NOT NULL,
  guardrails_fired     text[]      NOT NULL DEFAULT '{}',    -- enum, see below
  decision             text        NOT NULL,                 -- enum, see below
  refusal_code         text        NULL,
  refusal_user_message text        NULL
);

CREATE INDEX llm_call_log_ts_desc          ON llm_call_log (ts DESC);
CREATE INDEX llm_call_log_site_ts_desc     ON llm_call_log (site, ts DESC);
CREATE INDEX llm_call_log_decision_ts_desc ON llm_call_log (decision, ts DESC);
```

Backward compatibility: no `NOT NULL` columns without defaults — the
migration is safe to apply mid-rollout (Slice 5 ships before Slices
3/4 switch from `log.Printf` stop-gaps to `LogLLMCall`).

## Field semantics

| Field | Notes |
|---|---|
| `id` | Generated by the writer; not the LLM request id. |
| `ts` | Server time at the *start* of the LLM call. |
| `site` | See enum below. One row per LLM round-trip; a retry (Slice 4a/4b) writes a *second* row, not an update. |
| `model` | Whatever the call's `model` parameter actually was (e.g. `gpt-4o`, `gpt-4o-mini`, `gpt-4`). Important for cost / behavior diffs. |
| `user_id` | The acting user when known (always set for QA; nullable for worker-side calls). |
| `session_id` | The session the call was scoped to when applicable. |
| `prompt_hash` | `sha256` of the assembled prompt, hex. **Never log the prompt body** — too much PII + chunk content. The hash lets us de-dup retries / repeated questions for analysis. |
| `input_tokens` / `output_tokens` | From the LLM response. Nullable because the OpenAI client doesn't always populate them in error paths. |
| `latency_ms` | End-to-end wall-clock for the LLM call (does not include guardrail latency, which is negligible for rule-based and one-judge-call for the LLM-judge — measured separately). |
| `guardrails_fired` | Multiset of the guardrails that fired on this call (input *or* output side). Empty array means the call passed every check. Enum values below. |
| `decision` | One of `allowed`, `refused`, `redacted`. See enum. |
| `refusal_code` / `refusal_user_message` | Populated **only when `decision = 'refused'`**, matching the `code` and `user_message` from [`refusal-shape.md`](refusal-shape.md). |

### `site` enum

| Value | Source file |
|---|---|
| `qa_ask` | `internal/utils/qa.go` (RAG Q&A — both HTTP + MCP entry points) |
| `qa_ask_retry_citation` | `internal/utils/qa.go` retry round triggered by Slice 4a citation refusal |
| `qa_ask_retry_grounding` | `internal/utils/qa.go` retry round triggered by Slice 4b grounding refusal |
| `qa_grounding_judge` | `internal/guardrails/output.go` LLM-as-judge call (Slice 4b) |
| `action_items` | `internal/utils/action_items.go` |
| `decision_polish` | `internal/utils/polish.go` (decision extraction polish pass) |
| `obsworker` | `internal/obsworker/llm.go` |

### `decision` enum

| Value | Meaning |
|---|---|
| `allowed` | All guardrails passed; the response was returned to the caller. (May still have non-empty `guardrails_fired` if a *sanitization* fired — see `pii_redacted` / `schema_validation_failed`.) |
| `refused` | A guardrail blocked. `refusal_code` + `refusal_user_message` populated. The structured refusal shape was returned to the caller (see [`refusal-shape.md`](refusal-shape.md)). |
| `redacted` | Output was modified (e.g. PII redacted) but still returned. Reserved for future use; Slice 4c currently uses `allowed` with `pii_redacted` in the fired array. |

### `guardrails_fired` enum

1:1 with the `guardrail` slugs in [`refusal-shape.md`](refusal-shape.md),
plus the sanitization entries that don't produce a refusal:

- `input_injection`
- `input_off_scope`
- `input_too_long`
- `citation_missing`
- `grounding_failed`
- `pii_redacted` *(sanitization — not a refusal)*
- `schema_validation_failed` *(sanitization — record dropped)*

Adding a new value requires:
1. Add it here.
2. Add the matching refusal row to [`refusal-shape.md`](refusal-shape.md)
   (or note it as a sanitization-only entry).
3. The producing slice's PR uses the exact string.

## Writer contract (for Slices 3, 4a, 4b, 4c)

Until Slice 5 (SCRUM-568) ships, the slices emit a stop-gap log line:

```
event=GUARDRAIL_<INPUT|OUTPUT>_<REFUSED|FIRED> guardrail=<slug> code=<code> site=<site> user_id=<id> session_id=<id> latency_ms=<n>
```

Once Slice 5 ships, those calls switch to:

```go
guardrails.LogLLMCall(ctx, guardrails.LLMCallRow{
    Site:               "qa_ask",
    Model:              modelName,
    UserID:             &userID,
    SessionID:          &sessionID,
    PromptHash:         hashPrompt(prompt),
    InputTokens:        resp.Usage.InputTokens,
    OutputTokens:       resp.Usage.OutputTokens,
    LatencyMS:          int(elapsed.Milliseconds()),
    GuardrailsFired:    []string{"input_injection"},
    Decision:           "refused",
    RefusalCode:        ptr("input_injection"),
    RefusalUserMessage: ptr("Question detected to have unsafe content — not processed."),
})
```

The buffer is bounded; on overflow the *oldest* row is dropped (a
dropped row is itself counted as a metric — better to lose telemetry
than to add backpressure to the LLM critical path).

## Read patterns (informs index choices)

The `/api/admin/llm-stats?days=7` endpoint from Slice 5 will compute,
per the indexes above:

- `SELECT count(*), date_trunc('day', ts) FROM llm_call_log WHERE ts > now() - interval '7 days' GROUP BY 2` — `(ts DESC)` index.
- `SELECT decision, count(*) FROM llm_call_log WHERE ts > now() - interval '7 days' GROUP BY 1` — `(decision, ts DESC)` index.
- `SELECT refusal_code, count(*) FROM llm_call_log WHERE decision='refused' AND ts > now() - interval '7 days' GROUP BY 1` — same.
- `SELECT site, percentile_cont(0.95) WITHIN GROUP (ORDER BY latency_ms) FROM llm_call_log WHERE ts > now() - interval '7 days' GROUP BY 1` — `(site, ts DESC)` index.
